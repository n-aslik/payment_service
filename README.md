### **Payment Service with Commission Processing**
Сервис для обработки платежей с учетом комиссии (2%), интеграцией с внешним шлюзом и системой фоновых задач.
### 🚀 **Быстрый запуск**
Сервис полностью изолирован и запускается одной командой:
---------------------------
`docker-compose up --build`
---------------------------
После запуска сервис будет доступен по адресу http://localhost:8000. 
Также для создание схемы и таблиц Users и Transactions нужно запустить слудующую команду:
-----------------------------------------------------------------------------------
`docker exec -it postgres_db psql -U postgres -d firstdb -c "CREATE SCHEMA IF NOT EXISTS payment; CREATE TABLE IF NOT EXISTS payment.users
(
    id uuid NOT NULL PRIMARY KEY  DEFAULT gen_random_uuid(),
    balance numeric
);
CREATE TABLE IF NOT EXISTS payment.transactions
(
    id uuid NOT NULL DEFAULT gen_random_uuid(),
    user_id uuid REFERENCES payment.users (id) ,
    amount numeric,
    commission numeric,
    status character varying,
    idempotency_key uuid
)
"
`
------------------------------------------------------------------------------------
Все настройки осуществляются через переменные окружения в файле .env.🛠 
### 🛠 **Технологический стек**
- Язык: Python (рекомендуется использование асинхронных фреймворков для отзывчивости).
- База данных: PostgreSQL (таблицы пользователей и транзакций).
- Очередь задач: RabbitMQ (для работы фонового воркера).
- Контейнеризация: Docker & Docker Compose.
### 📖 Функционал системы 
1. Обработка платежей:
- Прием запроса (User ID, Amount).
- Автоматический расчет комиссии 2%.
- Имитация внешнего шлюза с обработкой ошибок (25%) и таймаутов (10%).
- Retry-логика с экспоненциальной задержкой (до 3 попыток).
2. Финансовый учет:
- Атомарное обновление баланса пользователя.
- Полная история операций (платежи и комиссии).
3. Надежность и мониторинг:
- Фоновая обработка тяжелых операций через воркеры.
- Эндпоинт /health для проверки статуса системы.
- Детальное логирование всех ключевых событий.
### 🧪 **Сценарии для проверки**
### *Для тестирования работоспособности можно использовать следующие кейсы:*
- Успешный платеж: создание → оплата → обновление баланса.
- Эмуляция сбоя: проверка работы механизма повторных попыток при ошибке шлюза.
- Таймаут: обработка зависшего запроса внешним сервисом.
- Проверка баланса: запрос состояния счета до и после транзакции.
### 📊 Дополнительные возможности (Bonus)
- Idempotency: защита от дублирования транзакций.
- DLQ (Dead Letter Queue): хранение задач, которые не удалось выполнить.
- Metrics: базовая статистика по успешным и проваленным платежам.
- API Doc: автоматическая документация (Swagger/ReDoc).
